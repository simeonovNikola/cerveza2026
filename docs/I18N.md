# French and English

next-intl 4 provides request configuration, dictionaries, locale URLs and a `NextIntlClientProvider`. Supported locales are `/fr` and `/en`; the root negotiates the saved locale/browser language, with French as fallback. Routes use the same neutral slugs in both locales, e.g. `/en/project/decisions`. `src/proxy.ts` excludes API/static files and persists the locale through next-intl's locale cookie.

`messages/fr.json` and `messages/en.json` contain identical namespaces/keys. Use `useTranslations('namespace')` and `t('key')`; add both versions together. Navigation, homepage, admin and search use semantic keys. Existing screens use an enumerated `ui.textNNN` catalog to preserve every existing behavior during migration; its French entry documents the original text. State labels use `states`.

Derived narratives are bilingual database overlays seeded from `scripts/english-content.mjs`. There is one canonical fact/question and one set of evidence relationships. Custom questions require French and English questions and answers; optional nuance has a field for each language. Missing translation should be treated as a defect, not silently filled with invented evidence.

Evidence titles, locator wording, paths and original extracted text remain in the original language. English summaries are explicitly labelled as translations. Original quotations are never overwritten or advertised as English originals. User-entered Impact events remain in the language supplied, with provenance visible.

The language switch preserves pathname, query and hash. Dates use `Intl.DateTimeFormat` with Montréal timezone and `fr-CA` / `en-CA`; narrative financial text has reviewed equivalent displays. `<html lang>` follows the route. No locale percentages or duplicate facts.

Validation: dictionary parity, EN/FR critical routes, language switching, absence of missing-key leakage, bilingual question CRUD, Ask NOVA and Impact regressions.

Final context checks cover locale changes inside an open evidence dialog, selected source/search query/filter and immediate Baseline toggling. The switch carries selected view explicitly rather than waiting for an asynchronous URL transition.
